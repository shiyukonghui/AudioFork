## 低延迟多输出音频路由软件需求设计说明书（V3.4 — 最终开发规格，含 GUI 前端）

### 1. 引言
#### 1.1 背景
在直播、现场扩声、多房间音频分发等场景中，需将一路系统音频输入实时、低延迟地同时传送至所有可用音频输出设备，并保证同步发声。本软件仅针对 Windows 10+ 与 macOS 11+ 平台。提供命令行和图形界面两种使用方式，以兼顾自动化与便捷操控。

#### 1.2 目标
基于 Rust 开发命令行/后台软件与可选的 GUI 前端：
- 选取系统默认或指定的音频输入设备。
- 以最低延迟将输入音频**复制分发**至所有有效输出设备。
- 自动适配采样率与声道数，确保音质，支持多种重采样质量等级。
- 热插拔时持续稳定运行，提供统计监控。
- GUI 提供直观的设备管理、参数调节、实时状态查看，不增加音频处理延迟。

---

### 2. 功能逻辑详细描述

#### 2.1 音频设备枚举与选择
**输入设备：**
- 枚举输入设备，支持 `--input-device` 指定；否则使用系统默认输入设备。
- 自动选择最优配置（f32、优先 48kHz、保持原生声道数）。

**输出设备：**
- 枚举所有输出设备，过滤无效设备。
- 可指定 `--output-device` 限定使用设备；默认使用全部有效设备。

**命令行参数：**
- `--input-device <NAME>`：指定输入设备
- `--output-device <NAME>`：可多次指定输出设备
- `--sample-rate <HZ>`：强制输入采样率
- `--channels <NUM>`：强制输入声道数
- `--buffer-frames <FRAMES>`：每个输出环形缓冲区容量（帧），默认 `max(128, 2 × 输入帧大小)`
- `--max-latency-ms <MS>`：最大允许延迟，用于校验 `--buffer-frames`，若换算延迟超过该值则拒绝启动（默认 30ms）
- `--resampler {sinc|cubic|none}`：重采样算法，默认 `sinc`
- `--no-drift-compensation`：禁用时钟漂移补偿
- `--exit-on-input-loss`：输入丢失时退出，否则保持运行并注入静音
- `--input-fallback-to-default`：输入设备丢失后，是否在 30 秒后尝试切换至系统默认输入设备（默认开启）
- `--log-file <PATH>`：日志文件路径
- `--monitor`：启用 JSON 行统计输出至 stdout
- `--wasapi-exclusive`：（Windows）尝试使用 WASAPI 独占模式（需编译时特性）
- **`--gui`**：启动图形界面（与 `--monitor` 互斥，GUI 内置状态显示）
- **`--config <PATH>`**：指定配置文件路径（默认 `audio_router.toml`）

**配置文件：** 启动时查找当前目录或指定路径的 `audio_router.toml`，命令行参数优先级更高。GUI 中的参数修改可同步到配置文件（可配置自动保存）。

#### 2.2 核心音频处理管道

**总体架构：** 采用每个输出设备独立的 SPSC 无锁队列（扇出模型），输入回调将音频数据写入所有活跃输出槽位。GUI 与核心引擎通过**消息通道**交互（非实时路径），绝不进入音频回调。

##### 2.2.1 输入采集回调
- 接收 `&[f32]` 数据，帧数固定。
- 向**所有活跃输出槽位**写入数据：
  - 遍历固定大小的输出槽位数组（最大 `MAX_OUTPUTS = 32`），仅处理活跃槽位。
  - **活跃判断**：使用 **Acquire** 内存序读取 `active` 标志（`AtomicBool`），确保看到对应槽位的 `Producer` 已完全初始化。
  - 对每个活跃槽位的 SPSC 队列执行写入：
    - 若剩余空间足够，直接写入。
    - 若空间不足，丢弃本次输入帧，记录溢出计数，继续下一槽位。
  - 回调中**无堆分配、无锁**（仅原子读和 SPSC 写入）。

**槽位结构与并发安全：**
- 槽位结构：
  - `producer: Option<RingbufProducer<f32>>`
  - `active: AtomicBool`
- **添加设备（主线程或 GUI 触发）**：
  1. 选择一个空闲槽位（`active == false`）。
  2. 创建 SPSC 队列及 `Producer`，填入槽位 `producer` 字段。
  3. 使用 `store(true, Release)` 设置 `active`，保证 Producer 初始化先于标志可见。
- **移除设备（主线程或 GUI 触发）**：
  1. 使用 `store(false, Release)` 将 `active` 置为 false。
  2. **不立即释放 Producer**，将其保留在槽位中。待该槽位被新设备复用时，直接替换旧 Producer。

##### 2.2.2 输出播放回调（每个输出设备独立）
每个输出设备拥有独立消费线程，回调请求填充 `output_buffer: &mut [f32]`。

**步骤：**
1. 计算本次需要从队列获取的输入帧数：
   - `ratio = Fs_in / Fs_out`，输出请求帧数 `N_out`。
   - `N_in_base = ceil(N_out * ratio) + filter_delay`（无重采样时 filter_delay=0）。
   - 漂移补偿增量 `delta`（整数，通常 -1/0/+1）由控制线程通过原子变量提供，实际需求 `N_in_target = N_in_base + delta`。
2. 检查 SPSC 队列可读样本数：
   - 若 `available_samples >= N_in_target * channels_in`：
     - 取出对应样本，送入重采样/声道映射流水线。
     - 若无重采样且声道相同（直通模式），直接拷贝至输出缓冲区。
   - **欠载处理（见 2.2.4）**：执行淡出淡入静音策略。
3. **重采样器状态连续性**：
   - 每个输出流维护一个 `resampler_clean` 标志。
   - 发生欠载时，设置 `resampler_clean = false`。
   - 恢复数据前，若 `resampler_clean == false`，向重采样器注入 `filter_delay` 个零样本帧（或调用 `reset()` 方法），使其内部状态清零后再处理真实数据，之后置 `resampler_clean = true`。

##### 2.2.3 智能直通与转换
输出流创建时判断：
- 输入采样率 == 输出采样率 且 声道数相同 且 未启用漂移补偿。
若成立，标记为**直通模式**，数据直接拷贝，零额外延迟。否则为转换模式。

**参数校验**：若用户指定 `--resampler none`（GUI 中对应选项），而输入输出采样率不同，则在启动时报错退出，提示需启用重采样。

##### 2.2.4 欠载与溢出平缓处理
- **溢出（生产者侧）**：队列满时丢弃整帧，不做特殊平滑；输出端将因此产生欠载。
- **欠载（消费者侧）**：
  - **模式区分**：
    - **直通模式**：若可用帧数 > 0，对最后 `fade_len` 帧信号执行余弦淡出，然后填充静音；若可用帧数 == 0，直接输出静音。
    - **转换模式**：若可用帧数不足 `N_in_target`，视为完全欠载，不尝试部分重采样（避免重采样器状态污染），直接输出静音并标记欠载。
  - `fade_len = min(5ms 等效帧数, callback_duration / 2)`。
  - 数据恢复时，从静音开始执行相同长度的余弦淡入。
- 余弦窗使用预计算 256 点表，线性插值查表，无运行时三角函数。

##### 2.2.5 时钟漂移补偿（帧数微调法）
- 每个输出流维护缓冲区水位的指数移动平均值（EMA，时间常数 3s）。
- 控制线程每 100ms 采集水位，与目标水位（缓冲区容量一半）比较，通过 PI 控制器计算该输出流的 **帧数增量 `delta`**（通常 -1/0/+1）。
- `delta` 通过原子变量传递给输出回调，回调据此调整 `N_in_target`，微调消费速率。
- 该方案不修改重采样器内部状态，绝对安全且无分配。
- 若使用 `--no-drift-compensation`，则 `delta` 固定为 0。

#### 2.3 同步与延迟控制
- **缓冲区容量**：默认 `buffer_frames = max(128, 2 × input_frames)`。启动时使用浮点校验：
  ```
  (buffer_frames as f64) * 1000.0 / (sample_rate as f64) > max_latency_ms
  ```
  若成立则拒绝启动，提示减小缓冲区或增大 `--max-latency-ms`。
- **启动同步**：使用带超时的就绪检测：
  - 每个输出流初始化时设置一个 `AtomicBool` 就绪标志。
  - 主线程（或 GUI 控制线程）在所有输出流创建后，等待所有标志置位（轮询 + 短休眠），超时 5 秒。
  - 超时未就绪的设备视为异常，跳过并从活跃列表移除，继续启动。
- **延迟预算**（48kHz，128 帧输入/输出，直通）：≈ 8.0ms，满足 <10ms 目标。

#### 2.4 设备热插拔处理
- **输出设备移除**：输出流错误回调触发，主线程将对应槽位 `active` 置 false，Producer 保留不释放。
- **新输出设备检测：**
  - **Windows**：使用 WASAPI 设备通知接口（底层 `wasapi-rs` 监听 `IMMNotificationClient`）。
  - **macOS**：使用 `coreaudio-rs` 注册 `kAudioHardwarePropertyDevices` 监听。
- 检测到新设备后，分配空闲槽位，创建队列和输出流，启动并立即参与分发。
- **输入设备移除**：
  - **阶段 1（0~30 秒）**：指数退避重连原设备（初始 100ms，×2，最大 5s，累计 30s）。
  - **阶段 2（30 秒后）**：若 `--input-fallback-to-default` 为 true，尝试切换至当前系统默认输入设备；否则继续重试。
  - 重连期间所有输出淡出至静音。
  - 若指定 `--exit-on-input-loss`，则在原设备断开后立即退出。

#### 2.5 启动与停止
**启动流程：**
1. 解析参数和配置文件。若 `--gui` 存在，初始化 GUI 窗口并显示，后续步骤由 GUI 事件循环驱动；否则按纯命令行流程。
2. 初始化输入设备，获取配置。
3. 参数校验。
4. 枚举输出设备，分配槽位，创建 SPSC 队列。
5. 创建所有输出流，启动流并等待就绪标志（带超时）。
6. 启动输入流。
7. 主循环：命令行模式监听 Ctrl+C 信号并维护热插拔；GUI 模式运行事件循环，通过轮询核心状态更新界面。

**停止流程（平滑）：**
1. 收到终止信号后，首先停止**输入流**。
2. 为每个活跃输出流设置 `fade_complete: AtomicBool` 标志。输出回调在完成淡出后将该标志置为 true。
3. 主线程**轮询**所有活跃输出流的 `fade_complete` 标志，超时 2 秒后强制停止。
4. 遍历所有输出流，执行 `pause()` 并释放资源。
5. 输出最终统计（命令行输出 JSON 行，GUI 在日志区显示）。

#### 2.6 错误与异常处理
- 输入流错误：按重连降级策略处理；重连期间输出静音。
- 输出流错误：槽位停用，记录错误。
- 致命错误：立即退出。

#### 2.7 声道映射规范
- 遵循 ITU-R BS.775 标准，采用保守增益：
  - 立体声→单声道：`Mono = 0.5*L + 0.5*R`
  - 5.1→立体声：`L' = 0.5*L + 0.35*C + 0.35*Ls`，`R' = 0.5*R + 0.35*C + 0.35*Rs`
  - 单声道→立体声：`L = Mono, R = Mono`
- **通用映射规则**（fallback）：按标准声道顺序映射到输出前 N 个声道，多余丢弃，不足填 0。
- 输出前可选**砖墙限幅器**（默认启用）：阈值 0dBFS，零攻击，10ms 释放。通过 `--no-limiter` 禁用时，专业环绕声下混可能削波。

#### 2.8 统计与监控
- **命令行模式**：`--monitor` 启用时，每 5 秒输出 JSON 行。
- **GUI 模式**：状态栏实时显示各输出的欠载/溢出次数、当前延迟估计、漂移 delta 等，不输出 JSON 到 stdout。

#### 2.9 图形用户界面 (GUI) 设计

##### 2.9.1 启动方式与架构
- 通过 `audio_router --gui` 启动，自动加载配置文件，若无则使用默认值。
- GUI 作为**控制前端**，核心音频引擎运行在独立线程中。GUI 与引擎通过**无锁消息队列**通信：
  - **GUI → Engine**：发送控制指令（启停、参数修改、设备切换等）。
  - **Engine → GUI**：推送状态更新（设备列表变化、缓冲区水位、错误事件）。
- 通信绝对不在音频回调中执行，确保零延迟影响。

##### 2.9.2 主窗口布局
采用单窗口分栏设计，尺寸可调，默认 900×700 像素。
- **顶部工具栏**：启动/停止按钮、配置导入/导出、帮助链接。
- **左侧面板（设备管理）**：
  - 输入设备下拉选择框，旁边显示当前采样率、声道数、格式。
  - 输出设备列表（可滚动），每个设备旁有复选框以启用/禁用，显示设备名称、采样率、声道、状态（直通/转换、活跃/断开）。
  - “刷新设备”按钮。
- **右侧面板（参数配置）**：
  - 缓冲区帧数滑块（32～4096，默认自动），实时显示对应延迟毫秒。
  - 最大延迟限制输入框（ms）。
  - 重采样算法下拉（Sinc / Cubic / None）。
  - 漂移补偿开关（勾选框）。
  - 独占模式开关（Windows 下可见）。
  - 输入丢失行为：单选按钮（退出 / 保持静默并重试，切换默认设备）。
- **底部状态栏**：
  - 引擎状态指示灯（运行/停止/错误）。
  - 每个活跃输出设备的实时指标：欠载计数、溢出计数、当前延迟 (ms)、漂移调整量 (delta)。
  - 全局 CPU 占用和内存占用（可选）。
- **日志/事件区域**（可折叠）：
  - 显示最近 100 条运行日志（带时间戳），支持复制和清空。

##### 2.9.3 交互逻辑
- **启动前**：用户可修改参数和设备选择，界面响应即时（仅改变 UI 状态）。
- **点击“启动”**：
  1. GUI 收集当前参数生成配置结构，通过消息通道发送给引擎线程。
  2. 引擎线程执行初始化流程（同命令行），启动成功/失败结果回传 GUI。
  3. 启动成功后，大部分参数锁定（缓冲区、采样率、重采样等运行时不可变更），仅允许**停止**或**动态设备启停**（启用/禁用输出设备的热插拔操作）。
- **运行时动态操作**：
  - 启用/禁用一个输出设备：GUI 发送添加/移除槽位指令，引擎执行槽位操作并回传结果。
  - 调整输入设备选择：仅在停止状态下允许，否则提示停止后再修改。
- **停止**：GUI 发送停止指令，引擎执行平滑停止流程，完成后通知 GUI 恢复参数可编辑状态。

##### 2.9.4 热插拔反馈
- 当引擎检测到新设备或设备移除时，主动推送更新到 GUI，GUI 刷新设备列表而不中断当前播放。
- 引擎中的状态变化（如某个输出流断开）自动反映在输出设备列表中（状态列变灰，复选框自动取消勾选）。

##### 2.9.5 GUI 实现技术选型
- **推荐框架**：`egui`（纯 Rust，即时模式，高性能，跨平台，与音频线程完全隔离）。
- **备选**：`iced`（Elm 式架构，但对实时更新支持需注意性能）。
- 选择 `egui` 的理由：
  - 即时模式渲染每帧更新，适合状态频繁变化（仪表板类界面）。
  - 无复杂生命周期，与核心引擎线程消息通信自然。
  - 已在多个音频工具中被验证（如 `vizia` 等亦可，但 `egui` 生态成熟）。
- GUI 线程以 30 FPS 刷新，避免不必要负载。

##### 2.9.6 GUI 非功能性需求
- **响应延迟**：用户操作（按钮点击、滑块拖动）到界面反馈 < 50ms。
- **资源占用**：GUI 自身内存 < 30MB，运行时总内存 < 80MB。
- **启动时间**：GUI 窗口显示 < 1 秒（不含引擎启动）。
- **兼容性**：支持 Windows 10+ 和 macOS 11+ 原生窗口，无需额外运行时。
- **可访问性**：基础键盘导航（Tab 键切换控件）。

#### 2.10 配置文件与 CLI-GUI 互通
- GUI 的“保存配置”按钮将当前界面参数写入 `audio_router.toml`。
- GUI 启动时自动加载配置文件，并在标题栏显示配置路径。
- 命令行参数可覆盖配置文件，但 GUI 启动时不处理命令行参数（除 `--config` 和 `--gui` 本身）。
- 提供 `--preset <FILE>` 参数（在 GUI 模式下，可从 File 菜单导入配置）。

### 3. 非功能性需求

#### 3.1 延迟分级目标
| 等级 | 延迟目标 | 平台前提条件 |
|------|----------|--------------|
| 理想 | < 10ms | Windows：WASAPI 独占模式（`--wasapi-exclusive`）或 macOS：CoreAudio 极低帧设置（≤ 128 帧） |
| 典型 | < 20ms | Windows：WASAPI 共享模式，macOS 默认，256 帧以内 |
| 兼容 | < 30ms | 所有模式，包括蓝牙等延迟较高设备 |

#### 3.2 性能
- 音频引擎 CPU 占用：4 个输出设备、48kHz 立体声、sinc 重采样下，单核心占用 < 5%。
- GUI 附加 CPU 占用：< 2%（30 FPS 刷新）。
- 内存：引擎常驻 < 50MB，GUI 附加 < 30MB，总计 < 80MB。

#### 3.3 稳定性
- 7×24 小时连续运行，时钟漂移补偿有效，无累积爆音。
- 设备热插拔不导致崩溃或死锁。
- GUI 崩溃不应导致音频引擎中断（进程内隔离通过线程实现，GUI 崩溃大概率导致程序退出，需保证 GUI 异常处理得当）。

#### 3.4 可用性
- GUI 提供清晰的状态反馈，所有控件带有 tooltip 说明。
- 错误消息以非阻塞弹窗或日志区红色文本展示。

### 7. 技术预研提示（开发启动前必读）

1. **跨库混用验证**：测试 `cpal` 与 `wasapi-rs` / `coreaudio-rs` 的流句柄共存。
2. **`rubato` 动态帧数与 API 行为**：确认 `SincFixedIn` 的输入帧数动态变化和状态重置方法。
3. **无锁槽位数组正确性**：使用 `loom` 或 `miri` 验证 Acquire/Release 内存序及 Producer 延迟释放。
4. **低帧数淡出效果**：128 帧@48kHz 下实装并听测 1.33ms 淡出，调整最小淡出长度。
5. **时钟漂移 PI 控制器调参**：在模拟漂移环境中调试 EMA 与增益，确保 delta 平滑。
6. **停止流程精确同步**：验证 `fade_complete` 轮询在多回调周期场景下的可靠性。
7. **GUI 与引擎消息延迟**：测量消息通道延迟，确保控制在 <1ms，不累积。
8. **GUI 框架兼容性**：确认 `egui` 在 macOS 和 Windows 上的原生外观与字体渲染，必要时自定义样式。
